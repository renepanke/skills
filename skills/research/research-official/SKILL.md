# Official

1. Identify the authority that owns the subject and the version, edition, or platform in the request. Carry forward a target established in the conversation. For an unspecified software version, use the current stable release and state the version or documentation track used.
2. Locate the canonical documentation from the authority’s own site or a documentation repository it designates. Search within those sources and open the matching pages. Use only official documentation as evidence, including API references, specifications, release notes, migration guides, and lifecycle notices published by that authority.
3. Check each proposed API, command, option, or procedure against the reference for the target version and the relevant official release notes, deprecation notices, or migration guides. Search for the exact identifier alongside terms such as `deprecated`, `removed`, or `legacy` within the official sources. Check the version selector, page notices, and release or removal dates. A page that still exists or a feature that still works does not establish current support.
4. Give only guidance that passes those checks and link directly to the supporting documentation. When an item is deprecated, report that status and any documented replacement that passes the same checks. If the official documentation is missing, inaccessible, or inconclusive about support, say what could not be verified and omit the unverified guidance.
